## C. 逐条说明与证据

### D1 问题二默认内核跑不出论文数
**问题**：`--core` 默认值是 `hybrid`（早期对照支），而论文 `result2.xlsx` 的口径是
`jia` 支。不加参数直接跑，得到的是**另一组数**，与论文对不上。

**修正**：`argparse` 的 `--core` 默认值 `hybrid` → `jia`，并把 `jia` 的 help 写成
"论文口径（默认）"，指出只有它复现 `21,463,158.37 kWh / 13,939,720.46 元`；
`hybrid` 明确标注"产出与论文不一致，仅供对照，不用于交付"。

**证据**：默认运行（无任何参数）——
```
【内核 jia】
计划购电量 21,463,158.37 kWh   计划购电费 13,184,221.29 元
弃电量 2,463,544.98 kWh   期末储电量 1559.72 kWh
本文风险修正策略（主模型） 13,939,720 元 ... 期末储电量 1,559.7 kWh
```
与论文 `21,463,158.37 kWh`、`13,939,720.46 元`、`弃电 2,463,544.98 kWh`、
`期末 1559.72 kWh` 全部一致。

**回归证据（最强）**：修正后用默认参数重跑，把 `输出/result2.xlsx` 与论文交付件
`06_支撑材料/result2.xlsx` 做**逐单元格**比对——
`计划购电量`/`充放电量`/`紧急购电量`/`全天汇总` 四张表，**差异单元格数 = 0**。
（文件字节数差 28B 仅为 xlsx 容器元数据，非数据差。）即 D1/D6/D8/D10 的改动
**没有动到任何一个数**，只把"假检查"换成了"真检查"。

### D2 问题三头条数字来源 / 两套实现"主口径"相反
**问题**：仓库里有两套问题三实现。`p3_rolling_microgrid.py`（早期建模库）的
`convention="main"` 指的是**不退款口径**；而论文 `main.tex:69` 声明**问题三主口径
是退款口径**。同一串 `"main"` 在两处含义相反，读代码容易误判论文数字来源。

**修正**：
1. 在 `p3_rolling_microgrid.py` 模块 docstring 顶部加 **D2 口径警示**，写明
   "本模块是早期版本，**不再产生论文中问题三的任何数字**；论文数字出自
   `p3_microgrid.py → p3_backtest.py → p3_export.py`"，并点破 `"main"`
   ≠ 论文"主口径"。
2. 新增自明别名 `CONV_NO_REFUND = "main"` / `CONV_REFUND = "refund"`，把
   "不退款" 这个真实含义写进常量名与注释；`"main"` 仅作兼容别名保留。
3. 把模块内 docstring/注释里的"主口径"改写为"不退款口径（token=\"main\"）"，
   但**不动** JSON 键名（如 `主口径最大下调量_kWh`），避免破坏既有输出格式。

**证据**：`p3_rolling_microgrid.py` 仍可被 `p4_microgrid.py` 正常 import
（`CONV_NO_REFUND` / `CONV_REFUND` 可读）。

### D3 论文说独立标定、docstring 说共用参数
**问题**：论文 `p4_section.tex:385`、`p4_tables_appendix.tex:62` 明确
"三种策略**各自独立标定**参数，用的是各自信息集下的历史"；而
`run_strategy_comparison` 的 docstring 写的是"三个价格模式**共用**同一组 1 月预热
参数"，代码也确实把同一份 `warmup42/43` 发给了三个模式。

**修正**：`run_strategy_comparison` 增加 `core` 与 `independent_warmup` 形参（默认
`True`）。开启时对 `forecast/fixed/oracle` **各调一次**
`select_warmup42/43(core, book, mode, ...)`，让每个模式按自己的信息集标定；结果表
新增 `1月标定` 列，把每个模式选中的 `(α,ρ,λ)` 写进对照表，便于审阅。想要回退旧
行为以复现历史数字时用 `--shared-warmup`（帮助文本已注明"与论文不符"）。

**证据**：接线自检（monkeypatch 记录桩）——
```
independent_warmup=True : select42/43 各收到 ['forecast','fixed','oracle']
                          run42 各模式 λ = [0.08, 0.05, 0.06]（互不相同）
independent_warmup=False: select 调用 0 次；三模式 λ 全为同一个 0.123
```

### D5 问题四缓存隔离"未佐证"
**问题**：`initial_plan4` 的缓存键是 `(tag, n, α, λ, e0)`，**价格不在键里**——价格
模式的区分完全压在 `tag` 上。若 `tag` 漏项，"先算的策略把计划塞给后算的策略"
这种错误**不会报错**，只会静默出错；而文档里只有"代码看起来是对的"这种论证。

**修正**：新增 `verify_cache_isolation()`，走**生产路径** `initial_plan4` 做四步
可失败检验，并加了 `--check-cache` 入口：
1. **正向**：同日同 `(α,λ,e0)`、两种必然不同的价格 + 两个不同 tag → 计划必须不同；
2. **命中**：同一 tag 重复调用 → 逐位相同；
3. **负向对照**：同一 tag、不同价格 → 第二次必然命中第一次的计划（因价格不在键里），
   这一步**证明本检查灵敏**——若生产代码真丢了 tag，行为就会退化成这个结果；
4. **顺序无关**：清空缓存、交换调用顺序 → 与正向逐位一致。

**证据**：
```
正向_不同tag计划最大差_kWh      1263.6281
正向_不同tag计划不同           True
命中_同tag重复调用逐位一致        True
负向对照_同tag不同价命中旧计划     True
顺序无关_交换调用顺序结果不变      True
结论                        通过
```

### D6 问题二六项检查硬编码"通过"
**问题**：原实现里"误差分位数只用过去数据""计划购电量在 0:00 冻结"两项
**直接 print "通过"**，不是检验；"通过（结构保证）"这种措辞也无法证伪。

**修正**：两项都改成**真会失败**的检验——
* 误差分位数：逐日把误差表截断到 `eps[:n]` 重算分位数，与当日记录的 `margin`
  逐位比对；若 `risk_margin` 读了未来行就会不等。（n=0 跳过）
* 计划冻结：把当日记录的 `n_risk` 与 `exec.E0` 重新喂回 `solve_dayahead`，得到的
  `g` 必须与执行层实际用的 `g` 逐位相同；若执行层在 0:00 之后改写过计划量，
  这一步会不等。（正式区间 334 天全查）

**证据**：默认运行日志——
```
误差分位数仅用当天之前已结束日期的误差 —— 通过（逐日把误差表截断到 eps[:n] 重算，364 天全部一致）
计划购电量在 0:00 冻结、执行层不修改 g —— 通过（把记录的风险净负荷重喂日前模型，334 天逐位一致）
```
（误差分位数一栏为 `364` 天，是因第 0 天无历史、按设计跳过。）

### D8 问题二状态累计检查是恒等式
**问题**：`ΔE = ηΣc − Σd/η` 这一条，因为 `E` 本身就是用同一条递推式生成的，
所以它**恒等于零**，不可能失败——把它当成"约束残差 2.3e-13"来报是错的。

**修正**：保留原式作**记录**（并改名叫"状态累计恒等式最大偏差"、注明不构成独立
校验），另加两条真会失败的判据：
* `状态重放最大漂移_kWh`：从 `E0` 出发按记录的 `(c,d)` 从零重放，与记录轨迹逐点
  比对 —— 抓"记录的 E 不是由这一段 (c,d) 产生"；
* 重放轨迹若越界 → 报"执行层发生过储电量静默截断"（`E_new = clip(...)` 会把越界
  悄悄抹平，属必须显式暴露的失效模式）。

**证据**：日志新增一行——
```
校验指标：供需平衡最大残差 2.274e-13 kWh（判定阈值 1.330e-03 kWh）；
  储电量越界最大量 0.000e+00 kWh；状态重放最大漂移 0.000e+00 kWh；
  状态累计恒等式最大偏差 1.319e-11 kWh（该量为恒等式偏差，仅作记录，不构成独立校验）；
  计划费/紧急费最大复算偏差 0.000e+00/0.000e+00 元
```
`p2_results.json` 的 `校验指标` 里新增 `状态重放最大漂移_kWh`；
"状态累计"那一项现在由**重放 + 越界**两条独立判据决定，恒等式偏差只作记录。

### D9 注释数字无脚本产出
